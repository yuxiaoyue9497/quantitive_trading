# TODO: 数据源质量问题

## 现状
datafeed/*.py 中 fetch_stock_data() 从 Baostock/AkShare/Tushare 获取数据，
但完全没有数据质量检查与验证。

## A股数据常见问题
1. **缺失数据**：某些交易日无数据（系统错误导致的数据缺失）
2. **重复数据**：同一天多条记录（罕见但可能发生）
3. **退市股票**：已退市股票的数据可能仍然存在，回测可能继续持有
4. **新股数据稀疏**：上市初期数据点少，均线可能不准确
5. **复牌缺口**：复牌后首日可能跳空开盘/收盘
6. **幸存者偏差**：当前数据只包含**现存**股票
   - 已退市股票的数据被剔除 → 回测只看到"幸存者"
   - 回测结果会显著高估策略效果（因为死掉的股票没被回测）
7. **停牌**：停牌期间的数据缺失

## 影响
1. **缺失/重复数据**导致均线计算错误（NaN 传播或重复信号）
2. **退市股票持续持有**：回测结果严重失真
3. **仅回测现存股票** → 幸存者偏差 → 回测结果乐观偏置
4. **复权因子缺失/错误** → 价格基准错误

## 实现建议
1. **数据验证**（fetch 后）：
   ```python
   # 删除重复
   df = df.drop_duplicates(subset='date')
   # 删除 NaN 行
   df = df.dropna(subset=['close', 'volume'])
   # 数据排序
   df = df.sort_values('date')
   ```
2. **退市检测**：
   - Baostock: `tradestatus` == 3 为退市
   - 检测退市信号，触发卖出
3. **幸存者偏差**：
   - 使用 **历史成分股** 数据（含已退市的股票）
   - 或使用 Tushare 的 `stk_list` 接口获取历史上市/退市信息
4. **新股处理**：
   - 新上市股票的前 N 日数据不参与均线计算（如 MA5 前 5 日无效）
5. **数据日志**：记录每只股票的数据质量信息（缺失天数、停牌天数等）
